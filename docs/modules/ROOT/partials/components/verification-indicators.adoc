=== Verification indicators

==== Verification icons

Verification icons are compact visual indicators that represent an actor’s verification state.
They should appear adjacent to the actor’s name and include accessible text or tooltips describing the credential issuer and verification details.

Icons must reflect the four distinct validation states defined in xref:_validation_states[Validation states]:

* *Trusted*: use a positive indicator such as a filled checkmark. Include the issuer name in the accessible label or tooltip.
* *Well-formed*: use a neutral informational indicator. Do not use a checkmark or any symbol that implies the issuer has been trusted. Do not use a warning symbol.
* *Validation incomplete*: use a neutral informational indicator, the same visual treatment as Well-formed. Do not use a warning symbol.
* *Revoked*: use a warning indicator to signal that the credential is no longer valid.

Unverified identities, such as names manually entered in metadata assertions, must not display a verification symbol.
These should be grouped and labeled to clearly distinguish them from identity assertions that have been evaluated.

Verification indicators must be perceivable to assistive technologies.
Color alone must not be used to convey meaning.

==== Status labels

Status labels provide a textual companion to the icon. They should be concise, localizable, and follow the tone and casing conventions used throughout the C2PA UX framework.

Recommended labels for each validation state are defined in xref:_validation_states[Validation states].
As a reference:

[cols=”1,2”, options=”header”]
|===
| State | Recommended label

| Trusted
| “Identity verified — issuer trusted”

| Well-formed
| “Identity present — issuer unrecognized”

| Validation incomplete
| “Identity could not be verified — network access required”

| Revoked
| “Identity credential was revoked”
|===

Labels should name the credential issuer where space allows so users understand the source of the trust decision.

==== Warning states

When identity credentials are revoked, expired, or trust-chain issues are detected, the indicator must shift to a warning state accompanied by a plain-language explanation of the issue and, where possible, a link to issuer or verifier details.

Neither a Well-formed nor a Validation incomplete outcome is a warning state and must not be displayed as one.
Both reflect limitations of the verification environment, not problems with the identity assertion or the named actor.
